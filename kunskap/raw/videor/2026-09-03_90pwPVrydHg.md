Grok Bot launched in August, still in beta, and most of the coverage stopped at the same line: an agent that works while your laptop is shut. The part nobody showed is that all your bots share one computer, so there's one browser and one set of logins between them. That's the whole difference, so we built a set of bots against our own product and gave them real work. This grok bot tutorial is the agent side of Grok, not a Grok 4.6 model review.

What Grok Bot actually is
- Each agent is a bot, and every bot runs on a computer online instead of yours, so work keeps going with your machine turned off.
- All your bots share that one computer. Same files, same browser, same logins: sign into an account once and every bot can use it.
- Bots message each other in a group chat, and you can schedule one to run at a set time.
- Setup is the app installer, then you create bots. Either chat with a bot until it writes its own profile, or type the instructions into its description.
- It has its own weekly usage limit, so what the bots do doesn't eat into the one you already use.

Grok bot vs hermes agent, and grok bot vs claude
- Hermes does the same basic thing. The difference is who owns the machine: with Hermes you set up and manage the computer, the tools, the browser and the logins. With Grok Bot that's handled and you just sign in.
- Claude Code can already drive a browser and test your app, but it isn't signed into anything. When a Grok Bot test comes back wrong, the lead bot can open Supabase and check what actually happened behind it.

The use cases we ran on our own product
- Multi-role testing. Our chatbot gives people different access depending on their role, so we made a bot per role plus a lead bot. Send the group a link, it assigns each bot its tests, each runs from its own screen, and it all comes back as one report.
- Support. A support bot on Gmail reads the unanswered emails and repeats each customer's steps in the browser. Login complaints usually aren't in the app at all, so it checks Supabase and Stripe to see whether the person actually paid. If the complaint is real it can fix it and open a pull request for you to approve.
- Churn. Your database and Stripe tell you who left, never why. A bot creates a fresh account and walks the flow as a first-time user, and every dead page, broken button and confusing instruction gets a screenshot.
- Competitor analysis. It stays logged into your competitors' products, so it can check them over time and report what changed: how their features actually work inside the product, not what the marketing page claims, and which ones yours lacks.
- AEO. People ask AI what to buy now, and you can't see whether you're the answer. A bot asks ChatGPT, Claude and Perplexity what a buyer would ask without naming your product, then reports where you showed up and where you didn't. We uploaded a skill so it also knows how to run the fixes.
- Monitoring. Payments, traffic and errors sit on separate dashboards, so one bot checks Stripe, our analytics and Sentry every morning. Tell it to attach a link or screenshot to everything, or you get a report you can't verify.
- Role building. A group with a product, marketing, support and growth bot, each with its own instructions. You talk to the product bot, it works out whose task it is, hands it over and reports back.

Running it from Claude Code or Codex
- A separate command line tool lets an agent do everything you'd do in Grok Bot yourself: create bots, give them tasks, run the whole thing. One install command from the repo above.
- Finish a feature, tell Claude Code to test it, and it sends the job to the group. The lead bot runs the round and you get one summary of what passed and what failed, without opening Grok Bot.
