# DTCG 2025.10

**Källa:** Design Tokens Technical Report 2025.10 – https://www.designtokens.org/tr/2025.10/ med modulerna Format (https://www.designtokens.org/tr/2025.10/format/), Color (https://www.designtokens.org/tr/2025.10/color/) och Resolver (https://www.designtokens.org/tr/2025.10/resolver/). Tillkännagivande 2025-10-28: https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/. Repo: https://github.com/design-tokens/community-group, commit 882ebd6 (2026-09-08). Startsidan https://www.designtokens.org/ visar 2025.10 som enda stabila version och ett levande utkast (https://www.designtokens.org/TR/drafts/). Läst 2026-10-16; specens text i detalj lästes 2026-10-13 (`kunskap/research/2026-10-15_kompetensluckor-anteckningar/lager-5-yta.md` §1).

**Licens:** Rapporterna har W3C Software and Document License; bidrag till specen går under W3C CLA (https://github.com/design-tokens/community-group/blob/main/LICENSE.md). Kräver bara att copyrightnotisen följer med om texten återges. Våra egna tokenfiler i formatet är våra.

**Vad det är:** Ett leverantörsneutralt JSON-format för designbeslut (färg, mått, typsnitt, skuggor med mera) som flera verktyg kan läsa. Version 2025.10 är gruppens första stabila version, en "Final Community Group Report" – uttryckligen ingen W3C-standard och inte på standardspåret.

**Hur det fungerar:**
- En token är ett JSON-objekt med `$value` och `$type`, i grupper. Filändelse `.tokens` eller `.tokens.json`.
- Typer: `color`, `dimension`, `fontFamily`, `fontWeight`, `duration`, `cubicBezier`, `number`, och sammansatta `strokeStyle`, `border`, `transition`, `shadow`, `gradient`, `typography`.
- Alias skrivs `{grupp.token}` eller med `$ref` (JSON Pointer).
- Färg är ett objekt med `colorSpace` (bland annat `srgb`, `oklch`, `display-p3`), `components`, valfri `alpha` och valfri `hex`-reserv.
- `dimension` får bara ha enheten `px` eller `rem`. `clamp()` och `vw` ryms alltså inte.
- Resolver-modulen beskriver teman: "sets" som alltid gäller och "modifiers" med "contexts" (till exempel `kit: lugn | varm | djarv`, `mode: light | dark`). Senare lager skriver över tidigare.

**Kvalitet och underhåll:** Repot har 2 149 stjärnor, 68 bidragsgivare och 96 öppna ärenden och PR:er; senaste commit 2026-09-08. Inga releaser på GitHub – versionen är rapportens datum. Öppna ärenden som rör oss: #188 "How to deal with 'fluid' dimensions" (sedan 2022, 14 kommentarer), #245 "Dimension type expanded unit types" (2024), #210 "Native modes and theming support" (60 kommentarer, löst i praktiken av Resolver) och #429 om rörelsetokens utöver `transition` (2026). Dokumentet bär två etiketter: omslaget säger "Final Community Group Report" medan statusavsnittet säger "Candidate Recommendation" (läst 2026-10-13).

**Det bästa vi kan ta:**
- Resolverns modell "sets + modifiers" som schema för stilkiten: en modifier `kit` med ett context per kit. Det är exakt "ett system, flera kit" (Resolver-modulen).
- Färgobjektet med `oklch` och `hex`-reserv (Color-modulen) som lagringsform för kitens färger.
- Tvånivåmodellen grundvärden → roller via alias, som guiden redan har (Brad Frost, `lager-5-yta.md` §1).

**Var det hamnar hos oss:** Ytskillen, `tokens.md`: formatet som kitens källa när kiten lintas och förnyas (guiden 2-5, N2). Inget skeppas – sajten får bara CSS. Ingen kontroll av formatet i sig; kontrollen ligger i Terrazzo (`tz check`).

**Passar vår stack?** Ja som källformat vid byggtid, 0 byte JavaScript per sida. Nu när Tailwind 4 är tillåtet (`BESLUT.md` 2026-10-16, kl. 12.28) kan samma tokens gå både till `--k-*` och till `@theme` via Terrazzo. Det som måste översättas: kitens `clamp()`-värden (typskala och sektionsavstånd) kan inte vara standardtokens. Lagra min och max som två `dimension`-tokens eller i `$extensions` och bygg `clamp()` i en egen transform (Terrazzos `transform`-alternativ, se kortet Terrazzo). Dagens kit (`bibliotek/stilkit/*/kit.css`) är handskriven CSS och måste skrivas om till JSON en gång.

**Risker och flaggor:**
- Ingen W3C-standard; motstridiga statusetiketter i dokumentet.
- Flytande mått saknas i standarden (öppet ärende #188), så en egen konvention behövs.
- Ingen licens-, telemetri- eller inloggningsfråga. Krockar inte med Lighthouse eller rörelsereglerna, eftersom inget skeppas.
